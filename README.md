# Flash Transfer

局域网文件快传第三版 MVP，默认离线优先，并针对大文件传输做了增强。

## 技术方案

- 前端：原生 `HTML + CSS + JavaScript`
- 配对与信令：`WebSocket`
- 点对点文件传输：`WebRTC DataChannel`
- 默认纯局域网直连，可选开启 `STUN`
- 房间规则：同一 4 位配对码最多 2 人，且必须是 `sender + receiver`
- 第三人进入同一房间时直接返回“房间已占用，不可配对”

## 本地启动

```bash
npm install
npm run dev
```

打开：

- `http://localhost:3000`

局域网测试时，把 `localhost` 换成当前机器的局域网 IP，例如：

- `http://192.168.1.10:3000`

## 测试方法

1. 打开两个浏览器窗口，或两台同局域网设备访问同一地址。
2. 一端选择“发送方”，另一端选择“接收方”。
3. 输入相同 4 位数字。
4. 配对成功后，发送方选择文件并发送。
5. 接收方如果浏览器支持，可先选择保存位置；否则接收完成后自动下载。

## 已实现能力

- 四位码配对
- 同码双人房间
- 角色冲突检测
- 第三人拒绝进入
- 设备名展示
- 多文件队列传输
- 拖拽上传
- WebRTC DataChannel 多文件逐个传输
- 文件级握手：声明、接收端就绪、完成确认
- 大文件优先走流式写入，避免内存堆积
- 发送/接收进度显示
- 房间超时释放
- 快速重新配对
- 可配置 STUN 服务器

## 当前限制

- 未接入 TURN，中继网络下仍可能失败
- 断线后需要重新配对
- 推荐使用 Chrome / Edge 测试
- 超大文件接收强依赖浏览器支持 `showSaveFilePicker`
- 未实现真正的断点续传和分片重传，长时间中断仍需重传

## 大文件模式

当前版本已经比前两版更适合大文件，尤其是单个 `10GB` 级文件，但前提是：

- 发送端和接收端网络稳定
- 接收端使用支持 `showSaveFilePicker` 的桌面浏览器
- 接收端在开始传输前手动选择保存位置

如果浏览器不支持流式保存：

- 小文件仍可回退为内存聚合后下载
- 超过 `512MB` 的文件会被主动拒绝，避免浏览器内存被打爆

## 离线模式

默认就是纯离线局域网模式：

- 不依赖公网 STUN
- 页面、配对、传输都只依赖你本机启动的服务和局域网连通性
- 适合无互联网环境

直接启动即可：

```bash
npm run dev
```

## STUN 配置

默认不启用 STUN。

如果你在某些复杂网络里需要额外打洞能力，再显式开启：

```bash
ENABLE_STUN=true
STUN_SERVERS="stun:stun.l.google.com:19302,stun:global.stun.twilio.com:3478"
npm run dev
```
